Flow Metrics — Privacy Policy

Effective August 21, 2026

Flow Metrics is built to work entirely in your browser. This page explains exactly what data exists, where it goes, and who can see it.

What Flow Metrics Stores

The only data the app holds is what you paste or type in: team names, an optional project id for each team, the names of any workflow stages you set up, and for each team a list of work items — a completed date, an optional start date, an optional created date, an optional work type, an optional issue key and, where your export carried them, which stage the item is currently in and a number of days against each stage — plus the shared settings (labels, the text that marks unplanned work, the thresholds, whether days are counted Monday to Friday, the work-type filter list) and your preferences (theme, chosen team, date window). No account is required to use the app, and there is no analytics, tracking or advertising of any kind.

The issue key is the one identifier the app keeps, and it is kept so that a dot on a chart can be named and then looked up in your own work system. It is checked against the shape of a key — up to ten letters or digits, a dash, and up to six digits, and nothing else — rather than trimmed to fit, so a cell that is anything other than a key is discarded whole. That check runs at the paste and again whenever a saved copy is read back. Before August 20, 2026 the app stored no key at all; a copy saved before then simply has none.

The project id is the letters at the front of those keys — DAE, for DAE-1552 — held against the team it belongs to so that one export covering several teams can be pasted in one go and split between them. It is checked against the same shape as the front of a key: up to ten letters or digits, starting with a letter, and nothing else. It is a label used to route a paste; it changes no figure, and it is never sent in a share link, because someone reading a link has nothing to paste.

Workflow stages are yours, and no status name from your export is ever stored. A stage is something you create and name in the app — Build, Review — and you tell the app which Jira statuses feed it by typing their names yourself. When you paste an export, the status names in it — whether they are column headings in a Time in Status export or the values in an ordinary Status column — are matched against what you typed, turned into a stage or a number of days, and then thrown away with the rest of the pasted text. From a Status column only work still in progress is filed at all; finished items are skipped. What is saved is the stage name you chose and a number. That is also why the app has no button that picks status names up out of an export: doing so would put work-system text into storage, which is the one thing it is built not to do. A share link carries the stage names and the day counts, because they are what the figures are; it does not carry the list of statuses you typed. Before August 21, 2026 there were no stages at all; a copy saved before then simply has none.

Note what is not stored: no ticket titles or summaries, no descriptions, no status names, no names of people, and no free-text or comment fields anywhere. Apart from the key, the app only ever needs dates, numbers and a type, and the work type is held to a short category label — a cell that looks like anything longer (a ticket summary, a description) is discarded rather than saved. The rest of what you paste is read for its dates and numbers on the spot and never stored.

Where That Data Lives

In your browser. That is the only place. Everything is stored in your browser's local storage on your own device. There is no server, no database and no account — the app has nowhere to send your data even if it wanted to.

A copy of the app itself, so it opens offline. The page, its stylesheet, its chart library and its icon are kept on your device — the same public files anyone can read on GitHub, and nothing else. Your work items are never put there. Clearing the site's browser data removes it along with everything else.

Cross-Device Sync Was Removed on August 20, 2026

Until that date the app offered optional Google sign-in, which mirrored your teams to a Firestore database in a Firebase project owned by the app's author. That feature is gone. The code, the sign-in button and every Google address were removed together, and the page's Content-Security-Policy now names no external origin at all — which is what makes this page's claims checkable rather than a promise. Any account id the old feature left in your browser is deleted the next time you open the app.

The data that had been stored there was deleted on the same day, so there is no copy of anyone's teams left in that database.

To use the app on more than one device now, use Back up to download a JSON file and restore it on the other device.

Share Links

The Share button builds a read-only link to teams you choose. The data travels inside the link itself — in the part after the #, which browsers never send to any server — so creating or opening one involves no upload, no download and no account, and nothing the recipient already has saved in their own browser is touched. A link is a frozen snapshot: it can't be edited through, and it can't be withdrawn once sent, so share it as deliberately as you would email a spreadsheet. It carries the same fields the app stores, issue keys included — they are what names the items on the charts, and a link without them would show the recipient a different picture from yours. It carries stage names and day counts for the same reason, but only the stages the items in the link actually spent time in.

What Is Never Sent Anywhere

  • Nothing you store in the app ever leaves your browser. There is no exception to this any more — the only way data leaves is if you deliberately create a share link or download a backup, and both of those are files you control.
  • There is no analytics, no tracking pixels, no advertising and no cookies.
  • The page loads no third-party code of any kind. Its chart library is a copy kept in the repository, served from the same address as the page itself.
  • The page's Content-Security-Policy sets connect-src 'none', so the browser itself refuses to let this page open a network connection — not to Google, not to the author, not anywhere.

Deleting Your Data

  • In this browser: "Clear this team's data" on the Your Data tab empties one team; deleting a team removes it entirely; Back up → Start again removes everything. Clearing your browser's site data does the same. That is the whole of it — there is no other copy to chase.
  • Anything left over from sync: nothing. The stored copies were deleted on August 20, 2026, along with the feature itself.

Changes to This Policy

If what the app stores or where it sends it ever changes, this page and its effective date change in the same release.
